# Chat-Codex v0.4 — Product Golden Path and Portable Desktop

Tracking: https://github.com/sidnvy/Chat-Codex/issues/3

## Intended first-run experience

A non-root Linux user with Node.js 22+ and Docker can establish a safe,
self-hosted development workspace without hand-editing JSON, connect to
ChatGPT after the user's own client authorization, and prove that an actual
authenticated MCP Client can run a small isolated coding task.

The first release target is **Linux + Docker**. Native macOS/Windows Host
installation and Desktop Runtime support are separate optional acceptance
targets; passing Charon tests does not certify Chat-Codex binaries.

### Proposed user journey (not all commands are implemented yet)

1. **Check:** `npm run doctor` or `npm run doctor -- --json` (initial
   implementation in the Doctor PR); read-only preflight, never reads token
   values or changes machine security policy.
2. **Configure:** a guided setup workflow (future PR) chooses the recommended
   Docker sandbox by default; persistent, unsandboxed Host/GUI execution
   requires explicit selection and clear consent.
3. **Connect:** guide the user through a securely reachable MCP endpoint,
   secret configuration and ChatGPT client authorization. This is not an
   automatic account-side Plugin installation.
4. **Verify:** an independent authenticated MCP Client proves real Docker
   lifecycle, code execution and result verification against disposable
   scratch data. Clean only test-owned resources; preserve user Projects.
5. **Discover:** read-only Home dashboard explains Projects, Environment,
   Host grants and Desktop permission/session state, with concrete next steps.
6. **Operate:** natural-language prompts for development, project testing or,
   when specifically enabled, snapshot-bound GUI observation and actions.

## Shared readiness vocabulary

Keep declarations, authorization, transport, and actual runtime readiness
separate. Diagnostics use the following local preflight classifications:

| State | Meaning |
| --- | --- |
| `ready` | This individual check was verified successfully |
| `action_required` | User must configure or start a prerequisite |
| `blocked` | Required platform/security/configuration condition failed |
| `warning` | Non-blocking risk or optional condition |
| `not_checked` | No claim of verification |

A process health endpoint does **not** prove MCP authentication or actual
Docker execution. A connected Host does **not** prove a ready Desktop session.
Never map a dispatched GUI action onto a verified result without an independent
observation. Unknown outcomes are not automatically retried.

## Implementation lanes

- **Doctor (P0):** Current read-only CLI with JSON output, installed on the
  development branch. Future additions may check an actual authenticated MCP
  handshake once local credentials are provided by a secure runtime, but must
  not print those credentials.
- **Guided setup (P0):** Reuse the existing restricted private config/token
  generator; no manual JSON edits; no silent overwrite. Docker recommended.
- **First-run acceptance (P0):** An actual authenticated MCP SDK Client over
  loopback, Docker scratch Environment, code/test/result evidence and cleanup.
- **Portable Desktop Core (parallel):** Driver Catalog, bounded one-time
  snapshots, identity rechecks and fail-closed readiness. Extract contracts,
  not private Charon/Coder transport implementations.
- **Drivers (optional):** Linux Hyprland, macOS Peekaboo and Windows native UIA.
  Every claimed platform requires its own Chat-Codex live E2E. Keep Windows
  Defender protections and signing/hash checks intact; no encoded PowerShell
  runtime or security-policy bypass.
- **Home/Skill/docs:** Capability dashboard, recommended first prompts,
  generic Observe → Act → Verify Skill, realistic troubleshooting and manual
  ChatGPT authorization guidance.

Keep these lanes in focused PRs. A Windows installation gap must not block the
safe Linux Docker Golden Path. Do not create another shared npm package until
portable interfaces are stable and conformance coverage justifies it.

## Initial Doctor contract

`npm run doctor -- [--config /absolute/path/config.json]` (human output); `npm run --silent doctor -- --json` (machine-readable output)

- Emits a bounded `schema_version:1`, `overall` and diagnostic `checks`.
- Is read-only: uses filesystem metadata, Docker info/image inspect and
  loopback health, not Docker provisioning or desktop mutation.
- Checks Linux/non-root/Node, config schema, private file permissions,
  Project directories, configured Docker image, local server and optional
  Desktop authorization declaration.
- Does not read token contents, validate remote ChatGPT account state or claim
  that OS GUI session permissions were verified.
- JSON can drive future Home/onboarding rendering without leaking secrets.

## Release/acceptance gates

- Fresh non-root Linux/Node 22+/Docker installation, zero manual JSON editing.
- Real authenticated MCP SDK first-run success, cleanup and explicit failure
  classification for missing Docker, invalid credentials and failed tests.
- CI unit/schema + real Docker integration + isolated plugin validation.
- Real desktop tests per OS separately labeled; no false passes for locked or
  uninstalled session-local drivers.
- Package, Plugin and MCP version alignment before eventual release.
- Reviewed merged Git main, deterministic artifacts, any installed Plugin
  publication requiring independent authorization and post-release verification.
