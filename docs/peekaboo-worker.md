# One-shot Peekaboo worker

`createPeekabooWorkerSource` from `chat-codex/desktop/peekaboo-worker` builds a dependency-free one-shot Host script from the installed canonical Peekaboo adapter, desktop primitives, command helpers, and native macOS session probe. It does not copy the adapter or require host-side npm installation, a listener, credentials, or security setting changes. The supported `chat-codex/desktop/macos-session` export exposes the same `macOSSessionProbe(run?)` used by the native acceptance harness.

Run the generated source through an admitted existing-user transport as `node -e SOURCE -- BASE64_JSON_REQUEST`. Requests are canonical base64 JSON capped at 8192 characters; responses are `{ok:true,result}` or `{ok:false,error}` and capped at 2 MiB. Operations are `status`, `windows`, `window` with an exact numeric `window_id`, and `act` with the previously returned window and private receipt. The worker profile exposes observed-element `invoke`, literal `type` text (1–500 JavaScript characters, no NUL), and one bounded `key` chord (at most 40 characters). Key chords accept the supported modifier names and named keys, F1–F12, or an ASCII letter/digit; sequences and arbitrary key syntax are rejected. All three actions require a fresh exact-window receipt and named capture snapshot. This profile does not expose pointer coordinates, foreground activation or targetless input. Model-facing schemas and Core's admission and single-use snapshot policy remain the provider's responsibility.

Trusted options are `timeoutMs` (100–28000, default 28000) and `maxImageBytes` (100–2097152, default 393216). An outer transport should retain its separate bounded timeout. Captures require actual PNG bytes, the task-owned exact file, and canonical process/window/session receipt revalidation. Empty or oversized captures fail closed. A native `CAPTURE_FAILED` response is reported as `capture_unavailable`; it is not proof of a locked session and must not trigger input retry. The canonical 30-second receipt lifetime is unchanged and checked immediately before dispatch. Failed native input is `outcome_unknown`, never retried automatically; accepted input remains `dispatched_unverified`, `verified:false`.

Fresh workers query at most 50 applications with four concurrent per-application window requests. Visible applications are prioritized before remaining background applications; results retain order within each group, completeness flags, and duplicate-ID rejection across the entire bounded inventory. This removes serial discovery latency without treating cached locators as authority or lengthening snapshot expiry. Every exact capture/action still validates current PID, native process-start identity, full title, and session evidence.

Every Peekaboo call selects the current user’s GUI Bridge socket explicitly. Readiness requires the expected GUI bundle identity, PID, process-start identity and signing hash, Bridge-sourced Screen Recording/Accessibility/input-synthesis permissions, and the native session probe. Bridge process replacement invalidates the derived session identity and existing receipts. Local CLI routing never counts as accepted mutation dispatch.

The native probe requires an existing non-root macOS console user, `python3`, and `/usr/sbin/ioreg`. It parses native plist evidence, requires exactly one logged-in on-console row owned by the current UID, and hashes the login UUID and session ID. Explicit `locked` is reported only when valid current-console identity accompanies `IOConsoleLocked=true`; missing or ambiguous evidence remains unverified. The probe does not unlock, switch sessions, change TCC, or establish that every capture backend is usable. Peekaboo permissions, capture checks, and outcome validation remain separate gates.

Status/errors suppress raw command text and native identity values. Window `app` prefers a bundle identifier and falls back to the application name; public titles remain bounded, and full title/process-start evidence stays in the private receipt. Optional observed string values are bounded to 200 characters; objects are omitted. Providers must keep receipts and session identity private when projecting MCP results.

Subprocess fixtures simulate macOS only inside test processes, with fake native commands. They test serialized-source execution, exact receipts, capture cleanup, deadline cancellation, session/process replacement, uncertain input, and bounded inventory concurrency. Native OS parsing is tested with fixture plists through actual Python. These tests do not substitute for real macOS acceptance.
